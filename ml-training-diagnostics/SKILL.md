# 학습 진단과 통제 실험

관측된 증거와 원인 가설을 분리하고, 최소한의 비교 실험으로 다음 조치를 결정합니다. 교재 없이도 표·그림·실험 기록만으로 판단 근거를 전달합니다.

## 작업 경계

평가 설계의 신뢰성은 [ml-model-evaluation](../ml-model-evaluation/SKILL.md), 누수 없는 분할·변환은 [ml-data-preparation](../ml-data-preparation/SKILL.md)의 범위입니다. [keras](../keras/SKILL.md)는 신경망 API 구현, [timeseries](../timeseries/SKILL.md)는 시계열 모델과 도메인 기준선, [pydeep](../pydeep/SKILL.md)는 환경 선택을 담당합니다. 이 스킬은 라이브러리와 관계없이 실제 학습 결과를 진단할 때 사용합니다.

## 진단 절차

1. 곡선의 x축이 epoch·최적화 step·표본 수·모형 복잡도 중 무엇인지 확인합니다. 같은 손실·평가지표·표본으로 비교하는지, 훈련 측정이 증강·dropout을 포함하고 검증 측정은 평가 모드인지 확인합니다. 정규화 항 포함 여부가 다르면 두 손실을 그대로 비교하지 않습니다.
2. 분할·중복·정답·특징 가용 시점·전처리 fit 범위와 평가 코드부터 확인합니다. 쉬운 기준선과 작은 훈련 부분에 대한 적합 가능성을 점검합니다. 작은 부분을 외우지 못한다고 바로 모형 용량 부족이라고 단정하지 말고 손실/출력·라벨·gradient·optimizer 연결도 확인합니다.
3. 훈련·검증 오차가 모두 높으면 표현력 부족뿐 아니라 최적화 실패, 정보 부족, 정답 잡음 등을 후보로 둡니다. 훈련 오차는 줄고 검증 오차가 증가하면 표본의 우연한 잡음에 대한 적합 등 과대적합과 부합하지만, 분포 변화·지표 차이·작은 검증 표본도 확인합니다. 한 번의 곡선만으로 원인을 확정하지 않습니다.
4. 발산·NaN에는 입력·라벨의 유한값, 손실과 출력의 일치, 학습률과 gradient 규모를 확인합니다. 정체에는 실제 파라미터 갱신, 동결 여부, 학습률, 포화, 데이터 파이프라인을 확인합니다. 매개변수 수만으로 일반화나 원인을 결정하지 않습니다.
5. 분할과 평가 조건을 고정하고 한 번에 설명 가능한 요인만 바꿉니다. 학습률·학습 시간·정규화·데이터 양·특징·모형 복잡도 중 가설을 구별할 실험을 선택합니다. 훈련 손실 감소가 검증 성능 향상·정체·악화 중 어느 결과로 이어졌는지 실측합니다. 최적화 개선이 반드시 일반화를 악화시키는 것은 아닙니다. seed나 분할 반복이 필요하면 결과 변동도 함께 기록합니다.
6. early stopping과 best checkpoint는 검증 데이터로 선택하고 시험 데이터는 진단·튜닝 반복에 사용하지 않습니다. 추가 실행의 비용·환경 제약과 사용자의 범위를 지킵니다. 증거가 불충분하면 가능한 가설과 가장 정보가 많은 다음 실험을 제시합니다.

## 결과물

관측 → 가설 → 확인 실험 → 결과 → 조치의 표, 축·단위·측정 조건이 명확한 곡선, 재현 설정과 미확인 사항을 제공합니다. 훈련 데이터의 신호와 우연한 잡음은 새로운 표본에 재현되는 관계인지로 설명하며, 잡음의 진짜 원인을 알지 못하면 특정 행을 잡음이라고 단정하지 않습니다.
